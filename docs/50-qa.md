# 50 — QA

Doc này định nghĩa **loại test nào bắt buộc cho loại thay đổi nào**, và các **drift guard** giữ docs khớp code.

> 🟢 **Ở Stage 0**, bar là: **test cô lập tenant** (Testcontainers) + **8 bước flow đầu-cuối** chạy tay trong `70-stages.md`.
> Drift guard, CI, golden test đầy đủ, kịch bản máy thật đều là **Stage 3+**. Đừng đòi hỏi chúng bây giờ.

---

## Nguyên tắc

Test ở đây không nhằm đạt phần trăm coverage. Nó nhằm chặn đúng **năm loại lỗi có thể giết công ty**:

| # | Lỗi | Hậu quả |
|---|---|---|
| 1 | Rò rỉ dữ liệu giữa tenant | Mất cả tỉnh — chủ quán ở tỉnh biết nhau hết |
| 2 | Sót đơn | Mất khách hàng đó vĩnh viễn |
| 3 | Sai tiền | Mất niềm tin ngay lập tức |
| 4 | Trắng màn hình storefront | Shop nghĩ sản phẩm hỏng |
| 5 | Docs/contract lệch code | Agent viết code sai theo doc sai |

Test không phục vụ một trong năm mục trên thì là "nên có", không phải "bắt buộc".

## Bảng: thay đổi loại nào cần test loại nào

| Bạn sửa | Bắt buộc có |
|---|---|
| Bất kỳ repository / query nào | Test cô lập tenant (có `findById`) |
| Trạng thái đơn | Test transition hợp lệ **và** không hợp lệ |
| Endpoint POST tạo thực thể | Test idempotency (gửi 2 lần → 1 bản ghi) |
| Endpoint public | Test DTO không lộ field cấm |
| Bất cứ gì đụng tiền | Test không có `double` (ArchUnit) + test snapshot giá |
| Block SDUI | Golden test + test unknown-block |
| Token / theme | Test parse config thiếu field vẫn chạy |
| Luồng nhận đơn merchant | **Kịch bản máy thật** (xem dưới) |
| Contract | `make verify-contracts` |

## 1. Test cô lập tenant — quan trọng nhất

Chạy trong CI. **Fail = chặn merge, không có ngoại lệ.**

```java
@Test
void tenant_b_khong_doc_duoc_du_lieu_cua_a() {
    var a = seedTenantWithOrders(3);
    var b = seedTenantWithOrders(2);

    withTenant(b, () -> {
        assertThat(orderRepo.findAll()).hasSize(2);
        assertThat(orderRepo.findById(a.orderIds().get(0))).isEmpty();  // ← dòng đáng giá nhất
    });
}
```

`findAll` bị filter là đương nhiên. **`findById` mới là đường rò rỉ thật** — ID lộ qua URL, qua log, qua đoán.

**Bắt buộc dùng Testcontainers**, không dùng H2. RLS là tính năng của Postgres, H2 không có — test trên H2 sẽ xanh trong khi production rò rỉ.

### Test cái bẫy connection pool

```java
@Test
void guc_khong_ro_ri_qua_connection_pool() {
    withTenant(a, () -> orderRepo.findAll());
    // mượn lại connection từ pool
    withoutTenant(() -> {
        var guc = jdbc.queryForObject("SELECT current_setting('app.tenant_id', true)", String.class);
        assertThat(guc).isNullOrEmpty();   // phải sạch
    });
}
```

Test này tồn tại vì `SET` thay vì `SET LOCAL` gây rò rỉ **im lặng** — không log, không exception.

### Coverage tự động

```java
@Test
void moi_bang_co_tenant_id_deu_bat_RLS() {
    var tables = jdbc.queryForList(
      "SELECT tablename FROM pg_tables t JOIN information_schema.columns c " +
      "ON c.table_name = t.tablename WHERE c.column_name = 'tenant_id'", String.class);
    for (var t : tables) {
        assertThat(rlsEnabled(t)).as("RLS chưa bật cho %s", t).isTrue();
    }
}
```

Test này bắt được bảng mới quên bật RLS — trường hợp hay xảy ra nhất.

## 2. Kịch bản máy thật cho merchant app
> ⚠️ **Stage 2.** merchant_app chưa tồn tại ở Stage 0.

Unit test **không đủ** cho app này. Trước khi đánh dấu xong bất kỳ tính năng nhận đơn nào:

| # | Kịch bản | Bar |
|---|---|---|
| 1 | Chạy nền **8 tiếng** trên Xiaomi và Oppo thật, gửi đơn | Chuông vẫn kêu |
| 2 | Khởi động lại điện thoại | App tự chạy lại, vẫn nhận đơn |
| 3 | Tắt Wi-Fi giữa lúc xác nhận đơn | Vào queue, tự gửi khi có mạng |

## 4. Drift guard — giữ docs khớp code
> ⚠️ **Stage 3.** Dựng cùng lúc với CI. Phần dưới để tham khảo khi tới lúc.

Đây là phần khiến bộ docs này còn đúng sau 6 tháng và sau khi đổi agent.

| Guard | Kiểm tra | Fail khi |
|---|---|---|
| `verify:contracts` | File sinh ra khớp `contracts/` | Ai đó sửa file generated bằng tay |
| `verify:blocks` | Registry Dart == `blocks.registry.json` | Thêm block trong code mà quên contract |
| `verify:openapi` | Spec sinh từ Spring == `openapi.yaml` committed | Endpoint đổi mà quên contract |
| `verify:tokens` | `DsTokens` + `tokens.ts` == `tokens.json` | Thêm token bằng tay |
| `verify:states` | Enum + bảng transition == `order-states.json` | Thêm trạng thái mà quên contract |
| `verify:metrics` | Công thức chỉ số ở BE == `metrics.json` | Web và BE tính khác nhau |
| `lint:hardcode` | Không `Colors.` / `Color(0x` / `BorderRadius.circular(<số>)` trong package dùng chung | Multi-style hỏng im lặng |
| `lint:money` | Không `double`/`float` trong package domain BE | Sai tiền |
| `lint:nativequery` | Không `nativeQuery = true` ngoài whitelist | Bỏ qua tenant filter |
| `verify:docs-links` | Mọi đường dẫn file trong `docs/` đều tồn tại | Doc trỏ file đã đổi tên |

Tất cả chạy trong `make verify-contracts` + `make lint`, và chạy trên mọi PR.

### Lint chống hardcode

```bash
if grep -rnE "Colors\.|Color\(0x|BorderRadius\.circular\([0-9]" \
     packages/ds_blocks/lib packages/ds_components/lib; then
  echo "❌ Hardcoded style trong package dùng chung"; exit 1
fi
```

Thô sơ nhưng hiệu quả. Không có nó, sau 3 tháng ~30% widget sẽ lén hardcode màu và multi-style hỏng **im lặng** — chỉ vài shop bị, không ai biết cho tới khi họ phàn nàn.

## 5. Test chống drift studio ↔ app

`customer_app` và `studio_web` dùng chung `ds_blocks`. Test này xác nhận điều đó vẫn đúng:

```
1. Render layout X trong customer_app → golden PNG
2. Render layout X trong studio_web preview → screenshot
3. So sánh, cho phép sai khác nhỏ (font rendering giữa mobile/web)
```

Nếu test này fail, ai đó đã dựng lại block ở phía web — đó là lỗi kiến trúc, không phải lỗi test.

## 6. Bug — quy trình

Mọi bug production được sửa phải kèm **một test tái hiện được bug đó**. Không có ngoại lệ.

Test viết trước (fail), rồi mới sửa (pass). Nếu không viết được test tái hiện, ghi lý do vào PR.

Bug thuộc năm loại ở đầu doc ⇒ đồng thời kiểm tra xem drift guard nào lẽ ra đã chặn được nó, và bổ sung guard đó.

## 7. Chạy gì trước khi báo xong

```bash
make lint && make test && make verify-contracts
```

Không tự nhận hoàn thành nếu chưa chạy. Nếu một lệnh không chạy được trong môi trường hiện tại, **nói rõ ra**, đừng bỏ qua im lặng.
